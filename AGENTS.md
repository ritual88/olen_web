# Правила работы над проектом

Сайт-визитка на Astro: статические страницы плюс одна серверная функция приёма заявки. Базы данных нет, пользователей нет.

## Как проверять работу

Задача не считается сделанной, пока не выполнен `npm run check` и его вывод не показан:

- `astro check` — типы в `.astro` и `.ts`;
- `node --test` — 25 проверок логики формы и обработчика заявки (без сети и без сервера).

Для проверки собранного сайта — `npm run verify`: собирает и прогоняет `scripts/audit.mjs` (один H1 на страницу, длина title и description, `alt`, битые ссылки).

Не писать «работает», «готово», «исправлено» без вывода команды.

## Чего нельзя ломать

| Что | Почему |
|---|---|
| Доставка заявки в Telegram | единственная функция сайта, ради неё всё и делалось |
| Honeypot `company` | без него форма станет спам-приёмником |
| Заголовки в `vercel.json` | CSP отключается одной опечаткой, и это не видно глазами |
| canonical и `sitemap.xml` | при смене домена забываются первыми |

## Правила правок

- Секреты — только в `.env` и переменных Vercel. В коде, тестах и логах их быть не может.
- Тест и код не править в одном заходе: сначала доказать, что тест краснеет, потом чинить.
- В тестах сеть подменяется: настоящий `fetch` в прогоне означает ошибку теста.
- Тексты — в `public/content.json`, не в разметке.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | локальный сервер |
| `npm run build` | сборка в `dist` |
| `npm test` | только тесты |
| `npm run check` | типы и тесты |
| `npm run verify` | сборка и проверка HTML |
